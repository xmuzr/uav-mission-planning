# 使用说明

## 环境与安装

安装 Node.js 22.21.1 或兼容的 Node.js 22/24，运行 `npm ci` 安装锁定依赖，再运行 `npm run dev -- --host 127.0.0.1`。浏览器需支持 WebGL；高德底图瓦片需要网络访问。

默认三维视图使用 `public/models/ruansan/tileset.json`。从 Release 下载模型包并解压至 `public/models/`。若出现模型 404，先直接访问 `http://127.0.0.1:5173/models/ruansan/tileset.json` 检查路径，避免解压成多层 `ruansan/ruansan/`。

## 创建任务

1. 在航线库中创建新航线，选择航线类型及飞行器、载荷配置。
2. 在地图上添加航点、绘制区域或中心线；三维任务按视图提示在模型上选择目标范围。
3. 配置高度或拍摄距离、相机参数、重叠率、速度及云台角。
4. 生成航线，检查航点、扫描行、覆盖预览与界面诊断信息。
5. 保存到航线库，或导出 KMZ 备份和进行后续设备端检查。

面状、倾斜和带状任务主要在地图视图中操作。斜面、几何体和精细贴近摄影任务使用模型视图；贴近摄影包含粗规划与精细阶段，需按界面流程切换。

## 坐标与高程

- 在线地图交互与三维模型来源可能采用不同坐标语义。`src/utils/coordTransform.js` 提供 GCJ-02 / WGS84 转换。
- 普通航点导出沿用其坐标转换路径；精细贴近摄影导出保留模型对应的 WGS84 经纬度和椭球高，相关行为有 KMZ 测试覆盖。
- 模型本身的地理配准决定规划结果位置。使用自己的模型时，需核对坐标系、单位、姿态及高程基准。
- KMZ 文件中包含 `template.kml` 与 `waylines.wpml`；具体动作、机型枚举和高度模式以生成文件及目标软件解析结果为准。

## 本地数据与备份

任务通过 `localStorage` 保存在当前浏览器和当前网址下。`127.0.0.1:5173` 与 `127.0.0.1:5174` 是不同的存储来源。更换端口或浏览器前，请先导出重要航线；本项目没有云端同步或账户数据库。

## 生产构建

```bash
npm run build
npm start
```

`npm start` 服务仅监听本机。默认尝试 5173—5193 端口，以终端输出为准。固定端口可在 PowerShell 中执行：

```powershell
$env:PORT = '5188'
npm start
```

修改源码或增加模型后需重新构建。不要直接通过文件协议打开 `dist/index.html`。

## 下载原始资料

Release 中的 `technical-document.docx`、`experiment-report.docx` 和 `route-planning-demo.pptx` 分别对应原交付的技术文档、无人机多类型航线规划实验报告和多模态航线规划演示。它们保持原文件内容，截图可能反映不同操作阶段。

当前源码目录没有 `bridge415.obj`，因此本次文档不沿用旧运行说明中“附带该 OBJ 模型”的描述。
